# Noosphere trust model

## What Noosphere relies on

- Walrus Memory encrypts memories with Seal before storing them on Walrus.
- Walrus Memory's Sui account contract controls owner and delegate access.
- The managed Walrus Memory relayer performs embedding, encryption, upload,
  indexing, download, and decryption.
- Project isolation uses the Walrus Memory `owner + namespace` boundary.

## What Noosphere itself does

- It validates and formats agent actions into a versioned memory envelope.
- It checkpoints workspace metadata without raw diffs by default.
- It can ask an AI model to evaluate an output only when
  `SCORING_MODE=remote` is explicitly enabled.
- It stores the evaluation beside the output so later agents can inspect it.

## Honest limitations

- The managed Walrus Memory relayer processes plaintext and embeddings.
- Remote scoring sends the action and recalled context to the configured AI
  provider. It is disabled by default.
- An AI evaluation is an opinion generated by the configured model. It is not
  trustless consensus and Noosphere does not present it as immutable truth.
- Semantic recall returns relevant results, not a guaranteed complete or
  chronological audit log.
- The compatibility `/agents` endpoint summarizes the recalled sample. It is
  not a global leaderboard.
- Demo mode persists to a local gitignored file, but it is not shared across
  machines, does not use Walrus, and should be treated as local plaintext
  development storage.
- Automatic checkpoints preserve observable workspace state, not unspoken
  reasoning. Session summaries or explicit memories are still needed for
  decisions that are not visible in files.

For a stronger privacy boundary, use Walrus Memory's self-hosted or manual
client flow. Public reputation or consensus scoring would be a separate
product and should not be implied by this implementation.
