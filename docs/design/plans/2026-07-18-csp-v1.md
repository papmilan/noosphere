# Continuation State Protocol v1 Implementation Plan

> **Architecture correction:** The measured-metadata design recorded below was
> superseded before review by
> `2026-07-18-csp-v1-durable-runtime-separation.md`. The normative `CSP.md` now
> defines a five-field durable tracked document; Git, agent, revision, identity,
> and timestamps are ignored runtime metadata. This file remains as execution
> history and must not be used as the current architecture.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the repository-only CSP v1 snapshot, transition boundary, deterministic merge/concurrency behavior, runtime-state migration, CLI separation from ACP, and documentation defined in `CSP.md`.

**Architecture:** CSP is a focused module under `noosphere-mcp/continuity/csp/`. Validation and merging are pure; storage owns safe UTF-8 reads, migration, file identity, locking, and atomic writes; transitions are the only public mutation API. The existing ACP modules remain unchanged except for CLI routing and documentation references.

**Tech Stack:** Node.js 22+ ESM, built-in `node:test`, JSON Schema 2020-12, Git CLI observation, existing Noosphere secure-filesystem and durability helpers.

## Global Constraints

- CSP v1 contains exactly the fields and semantics in `CSP.md`; no extension bag or v2 fields.
- `.noosphere/state.json` is canonical and Git-trackable; `.noosphere/runtime-state.json` is ignored runtime telemetry.
- The original checkout is never modified; all work remains uncommitted in `/private/tmp/noosphere-csp-v1` on `codex/csp-v1`.
- No cloud sync, database, networking, authentication, encryption, daemon, publish, tag, push, PR, merge, or release work.
- Production code follows strict red-green-refactor TDD.
